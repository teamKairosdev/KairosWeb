《Kairos AI 서비스톤 통합 기획안》

△ 서비스명: Kairos
△ 핵심 정의: 초개인화 AI 커리어 에이전트 플랫폼
△ 핵심 문장: 사용자의 경력, 삶의 맥락, 경험을 연결해 지금 필요한 다음 행동까지 실행하는 자율형 에이전트
△ 이름의 의미: Kairos는 그리스어와 성경에서 결정적인 시간, 가장 중요한 순간을 뜻한다.
△ 대회 트랙: AI 서비스톤
△ 문서 목적: 서비스 아이디어, 기능 구상, 기술구조, 심사기준 대응, 발표구성을 하나의 실행 가능한 기획으로 통합한다.

《1. 아이디어 정의》

- Kairos는 단순한 AI 자기소개서 작성 서비스가 아니다.
- 사용자의 이력서와 자기소개서뿐 아니라 업무기록, 학습기록, 프로젝트, 협업, 글쓰기, 커뮤니티 활동 등 흩어진 경험을 장기적으로 축적하고 해석한다.
- 사용자가 이직을 준비할 때만 작동하는 도구가 아니라, 평소의 삶과 일을 커리어 자산으로 전환하는 상시형 AI 에이전트다.
- 사용자의 목표와 상황을 이해한 뒤 필요한 자료를 찾고, 분석하고, 문서를 만들고, 수정하고, 버전을 관리하며, 다음 행동까지 연결한다.
- 조직은 조직원의 성장, 역량, 프로젝트 경험, 교육 이력, 커리어 방향을 관리하는 SaaS로 활용할 수 있다.
- Kairos의 차별점은 데이터의 양이 아니라 맥락의 연결과 실행의 연속성에 있다.
- 사용자가 직접 수정하고 승인할 수 있는 편집공간과 에이전트가 작업하는 공간을 하나의 캔버스로 통합한다.

《2. 문제 정의》

- 개인의 커리어 정보가 이력서, 포트폴리오, 노션, 깃허브, 메신저, 블로그, 교육기관, 채용사이트에 분산되어 있어 본인의 경험을 한눈에 파악하기 어렵다.
- 사용자는 실제로 많은 일을 했지만 무엇이 역량이고 어떤 성과로 표현되어야 하는지 정리하지 못한다.
- 이직이나 취업을 준비할 때마다 같은 정보를 반복 입력하고, 지원 공고의 논조에 맞춰 문서를 다시 쓰는 데 많은 시간이 든다.
- 기존 채용서비스는 공고와 지원서 관리에 강하지만 사용자의 장기적인 삶과 성장 맥락을 충분히 관리하지 못한다.
- 기존 생성형 AI는 답변을 만들어주지만, 긴 작업의 상태와 버전, 근거, 도구 사용 내역을 사용자가 신뢰하기 어렵다.
- 빈 캔버스형 AI 서비스는 자유도가 높지만 처음 무엇을 해야 할지 몰라 선택장애와 빈 화면 문제를 만든다.
- 개인과 조직 모두 자신의 경험 데이터를 안전하게 연결하고, 필요할 때 실제 결과물로 변환할 수 있는 작업공간이 필요하다.

△ 문제를 한 문장으로 정의하면 다음과 같다.
△ 사람들은 경험이 부족해서가 아니라 경험이 흩어져 있고 해석되지 않아서 자신의 다음 커리어 행동을 설계하기 어렵다.

《3. 타깃 사용자와 주요 상황》

- 취업준비생: 여러 경험을 직무 역량으로 연결하고 공고에 맞는 지원서와 포트폴리오를 만들고 싶은 사람
- 주니어 직장인: 매일 한 일을 기록해 성장과 이직에 활용하고 싶은 사람
- 경력직 이직 준비자: 프로젝트 성과와 협업 경험을 빠르게 정리하고 목표 기업에 맞춰 문서를 조정하고 싶은 사람
- 프리랜서와 창작자: 업무 산출물, 고객 피드백, 글과 프로젝트를 지속적으로 커리어 자산화하고 싶은 사람
- 커리어 전환자: 과거 경험을 새로운 직무의 언어로 번역하고 학습 계획을 세우고 싶은 사람
- 팀 리더와 인사 담당자: 조직원의 성장 기록과 역량 개발을 지원하고 싶지만 감시가 아닌 자율적 관리가 필요한 사람

《4. 핵심 가치와 차별성》

- 맥락: 한 번 입력한 이력만 보는 것이 아니라 사용자의 경험과 목표를 시간의 흐름 속에서 이해한다.
- 실행: 조언만 제시하지 않고 자료 수집, 분석, 초안 작성, 세밀한 수정, 다운로드까지 작업을 끝낸다.
- 통제: 에이전트가 수행한 작업, 사용한 도구, 참고한 자료, 변경된 문장을 사용자가 확인하고 승인한다.
- 연속성: 긴 작업의 상태와 이전 대화, 파일 버전, 사용자 선호를 보존한다.
- 성장: 취업이라는 특정 사건에만 반응하지 않고 매일의 경험을 장기적인 커리어 자산으로 전환한다.
- 관계: 비슷한 직무와 커리어 방향을 가진 사람을 연결해 혼자 준비하는 부담을 줄인다.

△ 벤치마크 서비스에서 참고할 강점
△ Gemini Canvas의 장점인 직접 수정 가능한 작업공간과 결과물 중심 경험
△ Claude의 장점인 긴 맥락 이해와 사용자 기억 활용 방식
△ Genspark 계열 서비스의 장점인 여러 도구를 활용해 결과물을 완성하는 에이전트 경험
△ Linear의 장점인 상태, 이슈, 작업 흐름, 변경 내역을 명확하게 보여주는 제품 경험
△ Kairos는 위 기능을 단순히 모방하는 것이 아니라 커리어와 삶의 맥락을 중심으로 재구성한다.

《5. 핵심 기능 구상》

《5-1. ATS 분석 기반 커리어 문서 평가》

- 채용공고를 입력하면 직무명, 핵심 역량, 필수 요건, 우대 요건, 산업 용어, 반복 키워드, 문장 어조를 추출한다.
- 이력서와 자기소개서의 키워드 일치도뿐 아니라 공고의 논조와 문서의 어조, 어휘, 구체성, 성과 표현을 함께 분석한다.
- 단순한 점수만 보여주지 않고 왜 부족한지, 어떤 경험을 추가해야 하는지, 어떤 문장을 바꾸면 좋은지 근거를 제시한다.
- 공고에 없는 과장된 키워드를 억지로 삽입하지 않도록 사실 기반 작성 원칙을 적용한다.
- 분석 결과는 적합도, 근거, 보완 우선순위, 수정 제안, 확인이 필요한 사실로 나눈다.
- 사용자는 문장을 직접 수정하거나 AI의 제안을 승인하고 거부할 수 있다.

《5-2. Deep Agent Canvas》

- 하나의 캔버스 안에 상단 작업영역, 중앙 대화 및 결과물 영역, 하단 프롬프트 입력창을 배치한다.
- 대화형 인터페이스와 문서 편집 인터페이스를 분리하지 않고, 대화의 결과를 바로 문서의 특정 부분에 반영한다.
- 에이전트의 내부 추론 원문을 그대로 노출하지 않고, 작업 단계, 판단 근거, 진행 상태, 사용한 자료를 요약된 작업 로그로 보여준다.
- 에이전트가 호출한 도구와 현재 상태를 예를 들어 자료 검색 중, 공고 분석 중, 문장 수정 중, 사용자 확인 필요와 같이 표시한다.
- 쉘 명령어나 웹페치 도구를 사용할 때는 Radius가 적용된 상태 카드로 사용 커맨드와 페치 URL을 표시한다.
- 장시간 작업은 백엔드가 할당한 VM 인스턴스와 작업 세션에 연결해 중단 후에도 이어서 처리할 수 있게 한다.
- 에이전트 루프가 이전 대화, 파일, 작업 상태, 사용자 승인 내역을 유지해 수십 분이 걸리는 작업도 연속적으로 처리한다.
- 사용자는 캔버스의 텍스트와 구조를 직접 수정하고, 특정 문장이나 블록을 선택해 편집 명령을 내릴 수 있다.
- 버전 기록에서 특정 시점의 결과를 확인하고 복원하거나 다운로드할 수 있다.
- AI가 매번 전체 답변으로 문서를 갈아엎지 않도록 tool_low_edit와 같은 세밀한 편집 도구 사용을 강제한다.
- 변경 전후의 diff를 제공해 추가, 삭제, 변경된 부분을 빠르게 검토한다.
- 문서, 프레젠테이션, 스프레드시트, HWPX 등은 지원 범위를 명확히 표시하고, 실제 구현이 완료된 형식만 시연한다.

《5-3. Career Community》

- 사용자의 직무, 경험, 관심사, 목표, 학습 방향, 커리어 전환 의향을 기반으로 비슷한 커리어 패스를 탐색한다.
- 단순한 직무 태그가 아니라 현재 단계, 목표, 필요한 역량, 관심 산업, 활동 패턴을 이용해 매칭한다.
- 비슷한 상황의 사람, 멘토, 스터디, 프로젝트, 콘텐츠를 추천한다.
- 개인정보를 직접 노출하지 않고 익명화된 관심사와 커리어 방향 중심으로 추천한다.
- 추천 이유를 설명하고 사용자가 추천 기준을 수정하거나 매칭을 중단할 수 있게 한다.

《5-4. Sea of your Contexts》

- Notion, GitHub, Samsung Notes, 잡코리아, 사람인, LinkedIn, 개인 블로그, Slack, Jira 등 다양한 데이터 제공자를 연결한다.
- 연결된 데이터는 원문 저장, 메타데이터 저장, 요약, 임베딩, 출처 정보로 구분한다.
- AI가 답변을 만들 때 어떤 문서와 기록을 참고했는지 출처를 표시한다.
- 사용자가 다른 AI 서비스에 저장해 둔 메모리나 사용자 선호를 가져올 수 있는 가져오기 양식을 제공한다.
- Kairos의 메모리를 JSON, Markdown, plain text 등의 형식으로 내보내 다른 서비스에 제출할 수 있게 한다.
- 공급자가 공식 API를 제공하지 않는 경우 사용자가 직접 파일을 업로드하거나 데스크톱 앱에서 자동화하는 대안을 안내한다.
- 웹에서 비정상적인 API 유사 요청을 하지 않으며, 이용약관과 개인정보 보호를 확인한 뒤 공식 연동, 사용자 수동 업로드, 데스크톱 자동화의 순서로 지원한다.

《5-5. 통합 AI 워크스페이스》

- 텍스트 분석, 이미지 생성, 문서 편집, 파일 변환, 웹 조사 등 작업 유형에 맞는 AI 모델과 도구를 하나의 워크스페이스에서 사용한다.
- 사용자가 보유한 무료 사용량과 연결된 서비스의 비용 정책을 고려해 적절한 모델로 작업을 라우팅한다.
- 생성된 이미지, 문서, 데이터, 파일을 사용자의 클라우드 서비스로 복사하거나 전송할 수 있게 한다.
- 파일을 외부로 보낼 때 대상, 파일명, 권한, 만료일을 확인하는 승인 단계를 제공한다.
- 작업마다 사용 모델과 사용량을 기록해 사용자가 비용과 품질의 관계를 이해할 수 있게 한다.

《5-6. 자체 AI 동작 라우트와 특화 SLM》

- 사용자의 명령, 이전 응답, 현재 컨텍스트, 목표, 작업 난이도, 개인정보 민감도, 예상 비용을 종합해 적절한 스킬과 모델을 선택한다.
- 간단한 분류, 요약, 형식 변환, 개인정보 마스킹은 가벼운 SLM으로 처리한다.
- 복잡한 추론, 장문 작성, 문서 비교, 다단계 도구 작업은 성능이 검증된 외부 LLM API로 라우팅한다.
- 엘리스 클라우드 등 사용 가능한 학습 인프라에서 기존 SLM을 파인튜닝해 커리어 문서 분류와 경력 근거 추출에 특화한다.
- 특화 SLM은 모든 작업을 대체하지 않고 빠른 보조작업과 서브에이전팅에 사용한다.
- 모델 선택 결과와 실패 시 대체 경로를 작업 로그에 남긴다.

《5-7. 서브에이전팅》

- 하나의 큰 과업을 자료수집, ATS 분석, 근거 검증, 문서 작성, 품질검수와 같은 작은 과업으로 분할한다.
- 각 서브에이전트는 독립된 컨텍스트와 제한된 도구 권한을 가진다.
- 병렬로 처리할 수 있는 작업은 동시에 실행하고, 서로 의존하는 작업은 순서대로 실행한다.
- 각 결과에는 담당 에이전트, 사용한 데이터, 완료 상태, 신뢰도, 다음 에이전트에 전달할 요약을 포함한다.
- 최종 에이전트는 하위 결과를 합칠 때 중복, 모순, 근거 부족을 검사한다.
- 사용자는 서브에이전트의 역할과 결과를 확인하고 특정 작업만 재실행할 수 있다.

《5-8. 매일 기록하는 커리어 로그》

- 하루의 업무, 학습, 협업, 문제 해결, 피드백, 결과물을 짧은 입력으로 기록한다.
- 사용자의 Slack, Jira, GitHub, 카카오톡, 개인 블로그 등에서 허용된 데이터를 가져와 기록 초안을 제안한다.
- 사용자가 승인한 정보만 장기 메모리와 커리어 타임라인에 반영한다.
- 기록을 역량, 성과, 협업, 리더십, 도메인 지식, 문제 해결과 같은 구조로 재분류한다.
- 하루 기록에서 포트폴리오 문장, 면접 답변, 회고 질문, 학습계획을 자동으로 제안한다.
- 사용자가 매일 부담을 느끼지 않도록 한 문장 기록, 음성 전사, 선택형 질문, 주간 요약 등 다양한 입력 방식을 제공한다.

《5-9. 진로 설계 도구》

- 만다라트, 역량 맵, 커리어 타임라인, 회고, 목표 분해, 행동계획, 가치관 탐색을 제공한다.
- 심리학적 기법을 진단처럼 단정하지 않고 자기이해를 돕는 질문과 선택지로 활용한다.
- 목표를 주간 행동과 실제 산출물로 연결해 계획이 실행되었는지 확인한다.
- 사용자의 상황에 맞지 않는 목표를 무리하게 추천하지 않고, 현재 자원과 제약을 함께 표시한다.

《5-10. 조직용 SaaS》

- 조직은 개인이 동의한 범위 안에서 팀 역량, 교육, 프로젝트 경험, 성장 목표를 관리할 수 있다.
- 개인의 사적 기록과 조직에 공유되는 업무 기록을 분리한다.
- 관리자는 개인의 모든 대화를 열람하는 방식이 아니라 구성원이 공유한 요약과 역량 데이터만 확인한다.
- 조직 대시보드는 채용, 온보딩, 역량 개발, 내부 이동, 교육 계획에 활용한다.

《5-11. 라이선싱 정책》

- 기본 방향은 Apache 2.0 기반의 오픈소스다.
- 코드, 모델, 데이터 커넥터, 호스팅 서비스, 조직용 기능의 권리와 책임을 구분하는 이중 라이선싱을 검토한다.
- 오픈소스 코어와 상용 호스팅 및 조직 기능의 경계를 명확히 문서화한다.
- 외부 모델, 데이터 제공자, 폰트, 오픈소스 라이브러리의 라이선스를 별도로 확인한다.
- 최종 라이선스 정책은 법률 검토를 거쳐 확정한다.

《6. 대회용 추천 MVP 범위》

△ 전체 비전은 크지만 대회에서 가장 중요한 것은 실제 구동되는 하나의 완결된 사용자 흐름이다.
△ 예선 시연은 다음 하나의 시나리오에 집중한다.

- 1단계: 사용자가 목표 채용공고와 기존 이력서 또는 경험 기록을 업로드한다.
- 2단계: Kairos가 공고에서 직무 역량, 핵심 키워드, 어조, 필수 요건을 추출한다.
- 3단계: Kairos가 사용자의 경험 기록에서 근거가 되는 프로젝트와 성과를 찾아 ATS 적합도와 보완점을 제시한다.
- 4단계: Deep Agent Canvas에서 사용자가 문장을 직접 수정하거나 에이전트에게 특정 문단만 고치도록 명령한다.
- 5단계: AI는 전체 문서를 덮어쓰지 않고 선택된 부분만 tool_low_edit 방식으로 변경한다.
- 6단계: 사용자는 diff, 근거, 버전 기록을 확인하고 승인한 뒤 결과물을 다운로드한다.
- 7단계: 완료 후 Kairos가 부족한 경험을 채우기 위한 다음 행동과 기록 질문을 제안한다.

《8. 프론트엔드 UXUI 중요사항》

- 마크다운 문법인데도 렌더링되지 않는 상황을 줄이기 위해 스트리밍 응답 중간에는 안전하게 표시하고, 응답이 끝난 뒤 몇 초 동안 마크다운 렌더링을 재시도한다.
- 재시도 횟수와 종료 조건을 두어 무한 반복을 막고, 렌더링 실패 시 원문 보기와 다시 시도 버튼을 제공한다.
- 이모지 문자는 사용하지 않는다. 상태와 감정은 텍스트, 색상, 아이콘, 배지로 명확하게 표현한다.
- 사용자가 뒤로가기나 탭 이동을 눌러도 입력 중인 프롬프트와 편집 내용이 초기화되지 않도록 임시 저장한다.
- 자동 저장 상태, 마지막 저장 시각, 저장 실패 여부를 보여준다.
- 에이전트가 작업 중일 때 단순한 로딩만 보여주지 않고 현재 단계, 진행률, 예상 다음 행동을 표시한다.
- 도구 호출은 사용자가 이해할 수 있는 언어로 표시하고, 쉘 명령과 웹 URL은 접을 수 있는 상세 영역에 보존한다.
- 내부 추론 원문을 그대로 노출하지 않고 작업 목적, 사용한 자료, 판단 근거, 결과 요약을 보여준다.
- AI가 내용을 변경할 때 변경 전후 diff를 제공하고, 부분 승인, 되돌리기, 다시 수정하기를 지원한다.
- 사용자가 무엇을 입력해야 할지 모를 때 최근 파일, 목표 선택, 추천 작업, 예시 프롬프트를 보여주어 빈 캔버스 문제를 줄인다.
- 사용자가 잘못 눌렀을 때 되돌릴 수 있도록 명확한 실행 취소와 복원 흐름을 제공한다.
- 개인정보나 외부 전송이 필요한 작업은 실행 전에 대상과 범위를 확인한다.
- 오류가 발생하면 실패 원인, 현재까지 보존된 결과, 다시 시도할 수 있는 방법을 함께 보여준다.
- 문서의 원본, AI 제안, 사용자가 승인한 버전을 서로 구분한다.
- 장시간 작업이 끝나지 않아도 사용자가 다른 화면으로 이동할 수 있고, 작업 완료 후 알림과 결과 위치를 제공한다.
- 모바일에서는 읽기, 승인, 간단한 기록을 우선 제공하고, 긴 문서 편집과 복잡한 도구 작업은 데스크톱에 최적화한다.

《9. 심사기준 대응》

△ 1. 문제 정의: 15점
▷ 핵심 주장: 사용자의 경험과 커리어 데이터가 여러 서비스에 흩어져 있어 자신이 가진 역량을 발견하고 적절한 문서와 행동으로 연결하기 어렵다.
▷ 구체적 문제: 반복 입력, 공고와 지원서의 어조 불일치, 기록의 단절, AI 작업의 비영속성, 빈 캔버스 문제를 하나의 흐름에서 해결한다.
▷ 증명 방법: 공고 입력 전후의 문서 분석 화면, 근거가 연결된 경험 카드, 작업 전후의 시간과 수정 범위를 보여준다.
▷ 주의점: 커리어 전체를 해결한다고 추상적으로 말하지 말고, 대회 시연에서는 채용공고에서 근거 기반 지원문서로 이어지는 문제를 명확히 보여준다.

△ 2. 기대 효과: 15점
▷ 개인 효과: 자신의 경험을 지속적으로 기록하고, 역량을 발견하며, 지원서와 면접 준비 시간을 줄인다.
▷ 사회적 효과: 개인의 비정형 경험이 평가 가능한 근거로 정리되어 경력 전환과 재취업의 기회를 넓힌다.
▷ 교육 효과: 목표를 행동계획으로 분해하고 학습과 실제 결과물을 연결한다.
▷ 조직 효과: 구성원의 성장과 역량 개발을 지원하는 지속 가능한 커리어 관리 체계를 제공한다.
▷ 지속가능성: 매일의 기록이 누적될수록 개인화 품질이 높아지고, 사용자가 다른 채용 이벤트가 없어도 서비스를 이용할 이유가 생긴다.
▷ 주의점: 개인의 성과를 단순 점수로 환원하거나 조직이 사적 기록을 감시하지 않도록 동의와 데이터 권한을 핵심 원칙으로 둔다.

△ 3. 창의성: 20점
▷ 차별 요소: ATS 평가, 개인의 장기 맥락, 직접 수정 가능한 에이전트 캔버스, 도구 실행 상태, diff와 버전 기록을 하나의 커리어 흐름으로 연결한다.
▷ 독창적 관점: 커리어를 이직 직전에 작성하는 문서가 아니라 매일 생성되는 경험 데이터로 정의한다.
▷ 사용자 경험 차별화: 자유도는 유지하되 추천 시작점과 단계별 안내를 제공해 빈 캔버스와 선택장애를 줄인다.
▷ 에이전트 차별화: 단순 답변 생성이 아니라 자료수집, 분석, 편집, 검증, 승인, 다운로드를 연속적으로 처리한다.
▷ 주의점: 기능을 많이 나열하는 것보다 하나의 사용자 사례에서 이 연결성이 실제로 보이게 해야 한다.

△ 4. 기술구현 및 완성도: 40점
▷ 필수 시연: 공고 업로드, 경험자료 입력, ATS 분석, 근거 연결, 부분 수정, diff, 버전 저장, 결과 다운로드.
▷ 에이전트 완성도: 진행 상태, 도구 호출, 오류 복구, 재시도, 작업 재개를 보여준다.
▷ 편집 완성도: 전체 답변 교체가 아닌 선택 영역 수정과 되돌리기를 구현한다.
▷ 데이터 완성도: 모든 분석 결과에 출처 또는 근거 문장을 연결한다.
▷ UX 완성도: 입력 보존, 자동 저장, 오류 안내, 마크다운 렌더링 재시도, 완료 상태를 구현한다.
▷ 안정성: 외부 API 실패, 잘못된 파일, 빈 입력, 네트워크 단절에 대한 대체 흐름을 준비한다.
▷ 구현 전략: 실제로 동작하는 MVP를 먼저 완성하고, 구현되지 않은 외부 연동과 HWPX 전체 편집은 향후 계획으로 구분한다.

△ 5. 발표: 10점
▷ 권장 이야기: 흩어진 경험이 채용공고에 맞는 근거 기반 문서로 바뀌고, 사용자가 변경 내용을 직접 승인하는 과정을 짧게 시연한다.
▷ 발표 원칙: 기능 목록보다 문제, 사용자, 전환 과정, 실제 결과물, 기술적 차별성을 순서대로 설명한다.
▷ 질문 대비: 데이터 출처, 개인정보 보호, AI 환각, API 비용, 장시간 작업, 실제 구현 범위를 솔직하게 답한다.

《11. 권장 데모 시나리오》

- 주인공은 2년 차 개발자이며 데이터 엔지니어 직무로 이직을 준비한다.
- 사용자는 채용공고와 기존 이력서를 Kairos에 넣는다.
- Kairos는 공고의 핵심 요건을 데이터 파이프라인, 협업, 문제 해결, 운영 안정성으로 분류한다.
- Kairos는 사용자의 GitHub 프로젝트 기록과 이력서의 경험을 연결해 근거가 있는 항목과 근거가 약한 항목을 구분한다.
- 사용자는 적합도 점수만 보는 것이 아니라 각 점수의 근거를 확인한다.
- 사용자는 특정 문단을 선택하고 운영 안정성을 더 구체적으로 표현해 달라고 요청한다.
- 에이전트는 선택한 문단만 수정하고 나머지 문서는 건드리지 않는다.
- 사용자는 diff에서 변경 내용을 승인하거나 되돌린다.
- Kairos는 최종 문서를 다운로드하고, 다음 주에 운영 안정성 경험을 보완하기 위한 기록 질문을 제안한다.

▷ 리스크: 메신저와 업무 데이터가 과도하게 수집되거나 조직 감시로 오해될 수 있다.

△ 단순 자기소개서 생성보다 문제의 범위와 장기 가치가 크다.
△ ATS 분석, 장기 맥락, 에이전트 실행, 편집과 버전 관리를 결합해 창의성 항목에 강하게 대응할 수 있다.

△ 현재 가장 큰 약점
△ 기능과 비전이 매우 넓어 심사위원에게 핵심이 흐려질 수 있다.
△ 다수 데이터 제공자, 여러 문서 형식, 장시간 VM 에이전트, 커뮤니티, SLM까지 한 번에 구현하려 하면 기술구현 및 완성도 40점에서 손해를 볼 수 있다.
△ AI가 무엇을 했는지 보여주는 것과 내부 추론 원문을 노출하는 것은 구분해야 한다.

△ 대회에서의 결론
△ Kairos의 전체 비전은 유지하되, 시연과 개발은 채용공고에서 근거 기반 지원문서로 이어지는 하나의 완결된 흐름에 집중한다.
△ 심사위원에게는 기능의 개수보다 사용자가 실제로 시간을 절약하고 자신의 경험을 더 정확히 표현하게 되는 장면을 보여준다.
△ 장기적으로는 Sea of your Contexts, Career Community, 통합 AI 워크스페이스, 자체 라우팅, 특화 SLM, 조직용 SaaS를 확장한다.
△ 한 줄 결론: Kairos는 사람의 경력과 삶을 계속 이해하면서, 결정적인 순간에 실제 결과물을 함께 완성하는 자율형 AI 커리어 에이전트다.

《16. 예선 심사위원 3명의 피드백 정리》

《16-1. 피드백 원문 보존》

아래 내용은 예선 심사위원 피드백의 메시지를 훼손하지 않기 위해 표현, 순서, 사례, 오탈자를 임의로 수정하지 않고 그대로 기록한다.

예선 심사위원 3명의 피드백 정리

- 기존 선행 시스템 비교조사(시장조사) 점검 등)(점검은 차별성찾기 중점으로) 제네시스랩 -뷰티인 HR, 사람인-모의면접, 자소서 진단 등 
- 사용자 관점에서 이력서 면접 데이터를 보고 관리할수 있도록 인터페이스 구성이 필요
- 채용공고 정보제공에 대한 구체적인 모습 기획 필요

- 같은 직무 및 채용공고에 여러 지원자가 있는 경우, Kairos로 생성된 이력서들이 유사할수 있고(형식 등) 차별되는 이력서가 나오지 않을 가능성이 과연 없는지 검토가 필요하다.
- 기존 비슷한 서비스들이 많으니 차별될 수 있는 추가기능(예: 여러 지원자 데이터로 내 순위 파악하기, 면접 응시 기능, AI 면접 피드맥에 대한 의견 수집 및 반영 시스템 구축) 등을 고려하면 좋을것으로 보인다.
- 발표시 충분한 서비스 내용을 설명할 필요가 있다.

- 먼저 지원회사나 지원 직무 조사를 선행하여 공부하고 이에 맞는 파편화 되어있는 자신의 이력이나 경력을 활용하는 시스템으로 완성도를 올리면 좋겠음

《16-2. 피드백을 쉽게 이해한 핵심 요구》

△ 요구 1. 기존 서비스와 비교해 Kairos만의 차별성을 증명해야 한다.
▷ 선행 조사 대상에는 심사위원이 언급한 제네시스랩 -뷰티인 HR, 사람인-모의면접, 자소서 진단 등 기존 서비스를 포함한다.
▷ 단순히 서비스 이름을 나열하는 것이 아니라 각 서비스가 해결하는 문제, 주요 입력, 제공 결과, 사용자 흐름, AI 활용 방식, 부족한 점을 비교한다.
▷ 비교조사의 목적은 기존 서비스를 비판하는 것이 아니라 Kairos가 어떤 사용자 문제를 추가로 해결하는지 확인하는 것이다.

△ 요구 2. 사용자가 이력서와 면접 데이터를 보고 관리할 수 있는 인터페이스가 필요하다.
▷ 이력서, 자기소개서, 채용공고, 면접 질문, 면접 답변, AI 피드백, 사용자의 의견, 버전을 하나의 커리어 자료실에서 관리한다.
▷ 문서와 면접 기록을 단순 파일 목록으로 보여주지 않고 회사, 직무, 지원 상태, 작성일, 최신 버전, 다음 행동과 연결한다.
▷ 사용자는 AI가 작성한 내용과 본인이 직접 기록한 내용을 구분해서 보고, 특정 자료를 수정하거나 삭제하거나 내보낼 수 있어야 한다.

△ 요구 3. 채용공고 정보가 화면에서 어떻게 제공되는지 구체화해야 한다.
▷ 채용공고 원문, 회사 조사, 직무 조사, 핵심 업무, 필수 요건, 우대 요건, 기술 키워드, 조직의 업무 방식, 예상 면접 주제를 하나의 공고 상세 화면에 배치한다.
▷ AI가 추출한 정보와 사용자가 직접 확인한 정보를 구분한다.
▷ 각 공고 정보에는 출처, 확인 시각, 신뢰도, 사용자 메모, 이력서와 연결된 근거를 표시한다.
▷ 공고 상세 화면에서 바로 회사 조사, 경험 매칭, 지원문서 작성, 면접 연습으로 이동할 수 있게 한다.

△ 요구 4. 같은 공고에 지원하는 사람들의 이력서가 비슷해지는 문제를 검토해야 한다.
▷ 모든 사용자에게 같은 문장과 같은 형식을 반복 생성하면 Kairos의 차별성이 약해지고 지원자의 개성이 사라질 수 있다.
▷ Kairos는 공고 키워드를 복사하는 것이 아니라 사용자의 실제 경험, 성과의 맥락, 문제 해결 방식, 선택의 이유를 근거로 문장을 구성해야 한다.
▷ 결과물은 공고 적합성, 사실성, 사용자 고유성의 세 축으로 점검한다.
▷ 이력서 형식도 하나로 고정하지 않고 직무, 경력 단계, 지원 목적에 따라 여러 구조를 제안하되 사용자가 최종 선택한다.

△ 요구 5. 기존 서비스와 구분되는 추가 기능을 검토해야 한다.
▷ 여러 지원자 데이터로 내 순위 파악하기라는 제안은 개인정보와 통계적 편향을 검토한 뒤, 실제 지원자 개인을 식별하지 않는 익명화된 비교 지표로 설계한다.
▷ 면접 응시 기능은 회사와 직무를 먼저 조사한 뒤 예상 질문을 생성하고, 사용자가 텍스트 또는 음성으로 답변하며, 답변을 다시 검토하는 흐름으로 설계한다.
▷ AI 면접 피드백에 대한 사용자의 의견을 수집하고, 도움이 되었는지, 사실과 다른지, 지나치게 일반적인지, 어떤 점을 보완해야 하는지를 다시 반영한다.
▷ AI 피드백을 일방적인 정답으로 취급하지 않고 사용자 피드백으로 개선되는 검토 시스템을 차별 기능으로 삼는다.

△ 요구 6. 발표에서 서비스 내용을 충분히 설명해야 한다.
▷ 기능 목록을 빠르게 나열하지 않고 한 명의 사용자가 회사와 직무를 조사하고, 흩어진 경험을 연결하고, 지원문서를 만들고, 면접을 연습하고, 결과를 관리하는 전 과정을 보여준다.
▷ 각 화면에서 사용자의 문제, Kairos가 수행한 작업, 사용자가 확인하고 결정하는 지점을 설명한다.
▷ 구현 완료, 시연 가능, 향후 계획을 구분해 기술구현 및 완성도를 과장하지 않는다.

△ 요구 7. 지원회사와 지원 직무 조사를 먼저 수행해야 한다.
▷ Kairos의 시작점은 자기소개서 생성이 아니라 지원회사와 지원 직무를 이해하는 것이다.
▷ 회사와 직무를 조사한 결과를 기준으로 사용자의 파편화된 이력과 경력을 필요한 역량에 연결한다.
▷ 이렇게 만들어진 문서는 공고의 문구만 반복하는 문서가 아니라, 해당 회사와 직무에 맞는 사용자의 실제 경험을 설명하는 문서가 된다.

《16-3. 피드백 반영 후 차별화 방향》

- Kairos는 이력서 생성기에서 회사·직무 조사부터 지원 이후의 면접과 회고까지 이어지는 커리어 의사결정 시스템으로 포지셔닝한다.
- 채용공고를 단순히 저장하거나 키워드로 분석하지 않고, 회사와 직무를 공부하는 첫 작업공간으로 만든다.
- 사용자의 자료는 이력서 문장으로 바로 변환하기 전에 프로젝트, 업무상황, 문제, 행동, 결과, 배운 점, 증거 링크로 구조화한다.
- AI는 구조화된 경험을 공고의 요구 역량과 연결하지만, 근거가 없는 성과나 키워드를 만들어내지 않는다.
- 최종 이력서는 공고 적합성을 갖추면서도 사용자의 실제 선택, 문제 해결 과정, 협업 방식, 성과 맥락이 드러나도록 작성한다.
- 면접 기능은 이력서 생성의 부속 기능이 아니라, 회사와 직무 조사 결과를 바탕으로 한 사전 연습과 사후 피드백의 순환 구조로 만든다.
- 사용자의 피드백을 AI 결과에 반영해 과도하게 일반적인 답변, 사실과 다른 분석, 사용자에게 맞지 않는 조언을 줄여간다.

《16-4. 기존 서비스 비교조사 계획》

△ 조사 목적
▷ 기존 서비스와 경쟁하려는 기능의 개수를 늘리는 것이 아니라, Kairos가 해결하는 고유한 문제와 사용자 흐름을 증명한다.

△ 비교 대상
▷ 제네시스랩 -뷰티인 HR
▷ 사람인-모의면접
▷ 사람인 자소서 진단 등 심사위원이 언급한 기존 서비스
▷ ATS 기반 이력서 분석 서비스
▷ AI 자기소개서와 면접 준비 서비스
▷ 직접 확인할 수 있는 국내외 채용 및 커리어 관리 서비스

△ 비교 항목
▷ 주요 타깃 사용자
▷ 해결하는 핵심 문제
▷ 회사와 직무 조사 제공 여부
▷ 채용공고 분석 방식
▷ 사용자의 경험 데이터 관리 방식
▷ 이력서와 면접 데이터의 연결 여부
▷ AI 결과의 근거와 출처 표시 여부
▷ 사용자가 직접 수정하고 승인하는 범위
▷ 버전 기록과 diff 제공 여부
▷ 사용자 피드백을 AI 결과에 반영하는 방식
▷ 지원 이후의 면접, 회고, 다음 행동 지원 여부
▷ Kairos가 추가로 제공할 수 있는 차별 기능

△ 비교표 작성 원칙
▷ 확인하지 않은 기능은 추측하지 않고 확인 필요로 표시한다.
▷ 기존 서비스의 장점도 함께 기록해 시장을 이해하고 있다는 점을 보여준다.
▷ 비교 결과는 기능이 더 많다는 주장이 아니라, Kairos가 회사·직무 조사, 개인 경험 근거화, 이력서·면접 데이터의 통합 관리, 사용자 피드백 순환을 함께 제공한다는 결론으로 연결한다.

《16-5. 사용자 관점의 화면 구성 보완》

△ 전체 화면 구조
▷ 회사·직무 조사 보드
▷ 채용공고 상세 화면
▷ 나의 경험 자료실
▷ 이력서와 자기소개서 작업공간
▷ 면접 준비 및 응시 화면
▷ AI 피드백과 사용자 의견 화면
▷ 지원 현황과 버전 기록 화면

△ 회사·직무 조사 보드
▷ 회사 개요, 사업, 제품 또는 서비스, 최근 공개 정보, 조직 특성, 직무의 역할을 정리한다.
▷ 조사한 내용은 출처와 확인 시각을 함께 기록한다.
▷ 사용자가 중요하다고 표시한 정보를 공고 분석과 면접 질문 생성에 전달한다.

△ 채용공고 상세 화면
▷ 공고 원문과 요약을 나란히 제공한다.
▷ 필수 요건, 우대 요건, 업무 내용, 기술과 도구, 협업 방식, 예상 평가 기준을 카드로 구분한다.
▷ 각 요구사항 옆에 사용자의 관련 경험, 근거 문서, 보완 필요 여부를 연결한다.
▷ 공고의 상태를 관심, 조사 중, 문서 작성 중, 면접 준비, 지원 완료, 회고 완료로 관리한다.

△ 나의 경험 자료실
▷ 업무, 프로젝트, 학습, 협업, 문제 해결, 피드백, 성과를 타임라인으로 보여준다.
▷ 각 경험에 기간, 역할, 행동, 결과, 증거 자료, 관련 역량, 공개 가능 범위를 기록한다.
▷ 사용자는 원문, AI 요약, 공고별 재구성 결과를 구분해 확인한다.

△ 이력서와 자기소개서 작업공간
▷ 공고와 연결된 문서만 모아 보여준다.
▷ 문서별 적합도, 근거 충실도, 고유성, 최신 버전, 사용자 승인 상태를 표시한다.
▷ 전체 다시 쓰기와 선택 부분 수정의 차이를 명확히 하고 기본값은 선택 부분 수정으로 둔다.

△ 면접 준비 및 응시 화면
▷ 회사와 직무 조사 결과에 근거한 예상 질문을 제공한다.
▷ 사용자가 질문별 답변을 작성하거나 음성으로 응시할 수 있게 한다.
▷ AI 피드백은 내용, 근거, 구조, 전달, 질문 적합성으로 나누어 표시한다.
▷ 사용자는 피드백에 동의, 일부 동의, 사실과 다름, 도움이 안 됨을 표시하고 이유를 남길 수 있다.

△ 지원 현황과 버전 기록 화면
▷ 회사별, 직무별, 지원 단계별로 이력서, 면접 답변, 피드백, 다음 행동을 묶는다.
▷ 특정 시점의 이력서와 면접 답변을 확인하고 다운로드하거나 복원한다.
▷ 지원 결과와 사용자의 회고를 다음 지원 전략과 커리어 기록에 반영한다.

《16-6. 피드백 반영 후 예선 MVP 수정안》

- 1단계: 사용자가 지원회사와 지원 직무를 선택하고 채용공고를 등록한다.
- 2단계: Kairos가 회사와 직무를 조사하고, 채용공고의 업무·요건·평가 포인트를 구체적인 화면으로 정리한다.
- 3단계: 사용자가 자신의 파편화된 이력, 프로젝트, 업무 기록을 입력하거나 업로드한다.
- 4단계: Kairos가 사용자의 경험을 구조화하고 회사·직무의 요구사항과 연결한다.
- 5단계: ATS 적합도뿐 아니라 근거 충실도와 사용자 고유성까지 함께 분석한다.
- 6단계: 사용자가 이력서 일부를 선택해 수정하고, AI는 선택 영역만 변경한다.
- 7단계: 사용자가 diff와 버전을 확인하고 결과물을 승인한다.
- 8단계: 같은 회사와 직무를 기준으로 예상 면접 질문에 응시한다.
- 9단계: AI 면접 피드백을 확인하고 사용자가 피드백의 유용성과 정확성에 의견을 남긴다.
- 10단계: Kairos가 사용자 의견을 반영해 답변을 다시 개선하고, 지원 이후의 다음 행동과 회고를 기록한다.

△ 예선 시연에서 반드시 보여줄 것
△ 회사와 직무 조사를 먼저 하는 시작 화면
△ 채용공고 정보가 구체적으로 정리된 화면
△ 사용자의 파편화된 경험과 공고 요구사항이 연결되는 화면
△ 일반적인 문장과 사용자의 고유한 근거가 반영된 문장의 차이
△ 이력서 및 면접 데이터를 사용자가 한눈에 관리하는 인터페이스
△ 부분 수정, diff, 버전 기록
△ 면접 응시와 AI 피드백
△ AI 피드백에 대한 사용자 의견 수집 및 반영

△ 예선 이후 확장할 것
△ 개인정보를 침해하지 않는 익명화된 지원자 비교 지표
△ 통계적으로 의미 있는 데이터가 축적된 뒤의 내 순위 또는 분포 확인 기능
△ 여러 외부 데이터 제공자 연동
△ Career Community 매칭
△ 조직용 커리어 SaaS
