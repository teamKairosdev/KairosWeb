《Kairos AI 서비스톤 통합 기획안》

△ 서비스명: Kairos (카이로스)
△ 핵심 정의: 초개인화 근거 기반 AI 커리어 에이전트
△ 대회용 핵심 문장: AI의 환각을 통제하고 사용자의 실제 경험 근거를 연결하여, 공고 분석부터 고유한 이력서 작성 및 면접 준비까지 일관된 맥락으로 완성하는 협업 작업공간
△ 이름의 의미: 그리스어로 결정적인 시간, 가장 중요한 기회의 순간을 뜻한다.
△ 문서 목적: 라이너(Liner)식 자가 검증 메커니즘과 CUI/인터랙션 개선을 반영하여, 심사위원을 매료할 완성도 높은 기획안으로 전면 개편한다.

《1. 30초 요약》

- Kairos는 단순히 그럴듯한 자기소개서 문장을 지어내 주는(Generative) 서비스가 아니다.
- 지원할 회사와 직무를 먼저 분석하고, 사용자가 입력한 실제 경험의 '팩트(근거)'만을 추적하여 매칭한다.
- 라이너(Liner)의 문장 단위 출처 제시처럼, AI 응답 생성 완료 후 백엔드에서 비보이지 않게 작동하는 '자가 검증(Self-Verification)' 프로세스를 통해 출처 누락 및 환각 오류를 자동으로 교정한다.
- CUI(채팅 UI)는 본문을 침해하지 않도록 정제된 크기로 배치하며, 렌더링 실패로 날것의 마크다운 기호(예: ** 등)가 노출되는 현상을 완벽히 차단한다.
- AI가 생각하고 작동하는 동안에는 텍스트 대기창 대신 사고 과정의 흐름을 동적인 UI 애니메이션 모션으로 시각화하여 사용자와 상호작용한다.

△ 심사위원이 기억해야 할 한 줄
△ AI의 거짓말을 차단하는 백그라운드 자가 검증과 사고 과정 시각화 모션으로 신뢰를 주는 자율형 커리어 작업공간

△ 대회에서 보여줄 최종 사용자 흐름
△ 지원 회사·직무 정보 탐색 ▷ 경험 근거 등록 및 공고 매칭 ▷ 자가 검증(Liner식 출처 대조) 및 고유성 분석 ▷ 캔버스 부분 편집 및 버전 관리 ▷ 예상 면접 응시 및 피드백 순환

《핵심 기능 5가지》

- 1. 지원 회사·직무 분석 (선행 분석)
  지원 회사의 주요 사업과 직무 핵심 업무를 탐색하고, 채용공고의 요건과 평가 포인트를 한 화면에 구조화하여 보여준다.

- 2. 경험 자료실 및 공고 요구사항 매칭
  사용자가 작성한 프로젝트, 업무 기록의 팩트(상황·행동·결과·산출물)를 공고의 세부 요건과 일대일로 연결하여 팩트 맵을 구축한다.

- 3. 라이너(Liner)식 자가 검증 및 고유성 점검
  AI 응답 후 백그라운드에서 실시간 검증을 실행하여 출처가 부족한 문장을 적발하고(자가 검증 상태 UI 표시), 일반적 AI 문체와의 유사성을 검출한다.

- 4. Deep Agent Canvas 기반 부분 편집
  전체 문서를 갈아엎지 않고 사용자가 선택한 특정 문단만 정밀하게 수정한다. 변경 전후의 차이(diff)를 확인하고 승인 여부를 결정한다.

- 5. AI 모의면접과 사용자 피드백 의견 반영
  작성된 이력서 근거를 바탕으로 모의 면접을 진행한다. AI 피드백이 적절한지 사용자가 동의/비동의 의견을 표기하여 다음 답변 개선에 반영한다.

△ 핵심 차별성 요약
△ 타 서비스처럼 문장을 자동 생성해주는 데 그치지 않고, 백그라운드 자가 검증을 통한 '근거 중심 작성'과 사고 과정 모션 UI를 통한 '상호작용 신뢰성'을 보장한다.

《2. 문제 정의와 타깃 사용자》

△ 문제 정의
△ 기존 AI 작성 서비스의 3가지 핵심 한계

- 1. 공장형 이력서 양산
  생성형 AI가 동일한 채용공고와 유사한 템플릿을 학습하여 답변을 만들기 때문에, 여러 지원자의 자기소개서 내용과 문체가 비슷해지는 역효과가 발생한다.

- 2. AI의 환각(Hallucination)과 과장
  AI가 자연스러운 문맥을 만들기 위해 사용자가 실제로 하지 않은 업무 성과나 경험을 임의로 지어내어 서류 전형 및 면접에서 신뢰도 문제를 일으킨다.

- 3. 준비 과정의 단절
  이력서 작성, 면접 준비, 데이터 관리가 각각 다른 툴(Notion, 사람인, 모의면접 앱)로 파편화되어 있어 이직 과정의 전체 맥락이 유지되지 않는다.

△ 주요 타깃
△ 취업준비생 및 주니어 이직자: 파편화된 경험에서 직무에 맞는 진짜 무기를 찾고 이력서와 면접을 일관되게 준비하려는 사용자

《3. 심사위원 피드백 반영으로 확정한 차별성》

△ 차별성 1. 지원회사·직무 정보 탐색의 선행
▷ 빈 문서에서 시작하지 않고 지원 회사의 사업 정보와 직무 요구사항을 먼저 파악하여 분석의 기준점으로 삼는다.

△ 차별성 2. 문장이 아닌 '경험 근거(Fact)' 중심 매칭
▷ 모든 문장은 사용자가 등록한 경험 자료의 팩트(상황-행동-결과)와 연결되어야 한다. 근거가 없는 문장은 UI상에서 경고 배지를 띄워 거짓 작성을 방지한다.

△ 차별성 3. 라이너(Liner)식 '자가 검증(Self-Verification)' 엔진
▷ AI가 문장을 완성하면 백엔드 시스템이 백그라운드로 작동하여 "경험 자료실(Fact DB)"의 원천 소스와 결과물의 각 문장을 교차 검증(Cross-check)한다.
▷ 화면에는 "자가 검증 진행 중..."이라는 상태가 표시되며, 출처 누락이나 왜곡을 감지하여 스스로 내용을 수정하거나 사용자에게 오류를 경고한다.

△ 차별성 4. 사고 과정 시각화 모션 UI
▷ AI 응답 시 단순 텍스트 스트리밍에 의존하지 않고, 에이전트의 사고 경로(자료 로드 ▷ 공고 대조 ▷ 자가 검증 ▷ 최종 텍스트 추출)를 모션 애니메이션과 카드 플로우로 표현하여 사용자에게 지루하지 않은 피드백을 전달한다.

△ 차별성 5. 고유성 분석(Uniqueness Check)을 통한 차별화
▷ 해당 직무에서 자주 쓰이는 진부한 표현이나 과도하게 일반적인 AI 문체를 점검하여 지원자만의 독창적인 서술 비율을 수치로 시각화한다.

△ 차별성 6. AI 피드백에 대한 사용자 피드백의 재환류
▷ AI의 면접 피드백에 대해 사용자가 '동의/비동의/사실과 다름'을 선택하고 정정 의견을 입력하면, 에이전트가 이를 기억하여 답변 개선안에 반영하는 대화 흐름을 제공한다.

△ 차별성 7. 사용자가 통제하는 작업공간(Deep Agent Canvas)
▷ AI가 최종 결과물을 강제하지 않으며, 사용자가 선택한 문단 수정, 버전 되돌리기, diff 검사 등을 통해 완벽한 통제권을 행사한다.

《4. 선행 서비스 비교조사》

△ 조사 기준일: 2026-08-01 (공식 서비스 소개 페이지 기준)

△ 비교 대상 1. 라이너 (Liner AI)
▷ 포지션: AI 검색 및 신뢰성 정보 제공 플랫폼
▷ 핵심 기능: 생성형 검색 답변의 문장 단위 출처 표기, 학술 데이터 연동 및 APA/MLA 인용 형식 제공
▷ Kairos와의 관계: 라이너가 웹상에서 정보의 신뢰성을 확보하기 위해 사용한 '문장 단위 출처 인용' 메커니즘을 벤치마킹하여, 구직자의 개인 경험 파일 및 팩트 기반 검증 엔진(자가 검증 프로세스)으로 확장 적용한다.

△ 비교 대상 2. 제네시스랩 뷰인터HR
▷ 포지션: 기업용 AI 채용 및 평가 에이전트
▷ 핵심 기능: 영상 면접 답변의 표정, 음성, 언어 분석을 통한 역량 평가 및 서류 검토 지원
▷ 차별점: 뷰인터HR은 '기업'이 지원자를 평가하고 걸러내기 위한 시스템인 반면, Kairos는 '지원자'가 스스로의 경험을 발견하고 주체적으로 준비하기 위한 개인용 협업 도구다.

△ 비교 대상 3. 사람인 AI 자기소개서 코칭
▷ 포지션: 구직자용 자기소개서 작성 보조 도구
▷ 핵심 기능: 공고 맞춤 초안 생성, 오탈자 교정, 진부한 표현 코칭
▷ 차별점: 사람인은 단발성 문장 수정과 키워드 추천에 머무르는 반면, Kairos는 경험의 구조적 매칭을 통해 문장의 '진위 여부(근거)'를 판별하고 이를 면접 준비 데이터로 직접 연동한다.

△ 비교 대상 4. 사람인 AI 모의면접
▷ 포지션: 구직자용 면접 연습 서비스
▷ 핵심 기능: 이력서 기반 질문 생성 및 답변 분석 리포트 제공
▷ 차별점: 모의면접 도구가 이력서 작성 환경과 완전히 분리되어 있는 반면, Kairos는 이력서 수정 내역이 면접 질문에 실시간으로 반영되고 면접 피드백을 통해 다시 이력서를 고치는 순환 아키텍처를 제공한다.

《5. 기능 정의 (대회용 MVP 중심)》

△ 기능의 구조적 핵심
△ 본 대회에서는 개발 현실성을 확보하기 위해 '개인 대시보드'와 'AI 작업공간(Deep Agent Canvas)'의 유기적 흐름에 집중하고, 확장 기능(커뮤니티, 외부 API 연동)은 장기 로드맵으로 분리한다.

《5-1. 개인 대시보드 및 작업공간》

- 1. 프로젝트/경험 자료실
  사용자가 자신의 프로젝트 경험, 성과 지표, 배운 점 등을 팩트 카드 형태로 작성하고 저장하는 공간. (예선 MVP에서는 텍스트 및 마크다운 수동 입력 지원)

- 2. 채용공고 분석 보드
  지원하려는 채용공고의 요건(필수/우대 요건, 핵심 업무)을 카드 형태로 구조화하여 시각적으로 보여주는 보드.

- 3. 경험-공고 매칭 맵
  채용공고의 요건 카드와 사용자의 경험 팩트 카드를 연결하여 매칭 적합도를 점검하고, 매칭되지 않은 공고 요건을 찾아내어 보완할 수 있도록 제안한다.

- 4. Deep Agent Canvas (AI 문서 작업공간)
  - 화면 좌측: 현재 작성 중인 이력서/자기소개서 에디터 (수동 편집 및 AI 부분 편집 가능)
  - 화면 우측: 에이전트의 판단 근거, 작업 로그(사고 과정 모션 UI), 매칭된 경험 카드
  - 핵심 동작: 마우스로 블록 지정한 특정 영역만 AI에게 수정 요청(tool_low_edit 강제 적용), 백그라운드 자가 검증(자가 검증 상태 UI 가동), 변경 사항에 대한 시각적 diff 제공, 버전 관리 및 복원 기능.

- 5. AI 모의 면접 및 피드백 순환기
  - 작성된 최종 문서를 기반으로 예상 면접 질문 생성.
  - 사용자는 텍스트로 면접 답변을 입력.
  - AI의 평가 및 피드백 제공 ▷ 사용자가 피드백에 대해 의견을 입력(예: "이 부분은 내 프로젝트의 다른 제약 사항 때문이었습니다") ▷ AI가 이를 반영해 최종 답변 보완안 제시.

《5-2. 장기 로드맵 기능》

- 1. Career Community (커뮤니티)
  - 개인정보를 가린 익명화된 커리어 패스 매칭.
  - 동일 직무 지원자들의 유사성 분석 및 분포도 분석을 통한 포지셔닝 제안.
  - 면접 답변 및 포트폴리오에 대한 피어 리뷰(Peer Review) 그룹 구성.

- 2. Sea of Contexts (외부 데이터 통합)
  - GitHub Repository 기여도 분석, Notion 프로젝트 페이지 연동, LinkedIn 프로필 연동을 통한 경험 카드 자동 생성 기능 (OAuth API 권한 분리 적용).

- 3. 통합 AI 워크스페이스 및 하이브리드 라우팅
  - 간단한 오탈자 검사나 팩트 분류는 경량 SLM으로 처리하고, 상세 이력서 작성 및 면접 피드백은 대형 LLM으로 분기하여 효율성과 비용을 최적화하는 라우터 아키텍처.

《6. UXUI 구현 원칙》

- 1. 텍스트 중심의 정제된 UI
  이모지 사용을 엄격히 제한하고, 상태 변화(작업 중, 완료, 경고)는 세련된 배지(Badge)와 HSL Tailored 컬러 시스템으로 표현한다.

- 2. 마크다운 렌더링 디바운싱 및 재시도 메커니즘
  스트리밍 중인 텍스트가 불완전하여 원문 기호(예: ** 등)가 날것으로 드러나지 않도록 버퍼링/디바운싱 필터를 적용하고, 최종 스트리밍 종료 후 완벽한 구조의 마크다운이 표현될 때까지 재시도를 수행한다.

- 3. 고집적 컴팩트 CUI (Chat UI)
  메인 작업 공간인 캔버스를 보조하도록 채팅 창은 작고 정제된 텍스트 위주로 답변을 제공하여 사용자의 시각적 분산을 차단한다.

- 4. 사고 과정 시각화 모션 UI
  AI 대기 시간 동안 정적인 로딩 스피너 대신, AI의 생각의 흐름(예: 공고 요건 대조 중 ▷ 팩트 데이터 추출 중 ▷ 문장 생성 중 ▷ 자가 검증 중)을 동적 아이콘 모션과 진행 상태 바 형태로 보여주어 작업 신뢰감을 극대화한다.

- 5. 입력 상태 보존 원칙
  사용자가 입력 창이나 편집 도중에 실수로 화면을 이탈하거나 탭을 변경하더라도 입력 중이던 텍스트와 프롬프트가 유지되도록 Local 임시 저장 기능을 적용한다.

- 6. 직관적인 Diff 뷰어
  AI가 추천한 수정본을 즉시 덮어쓰지 않고, 기존 문장과 수정 제안 문장을 대비하여 보여주는 인라인 Diff 인터페이스를 제공한다.

《7. 기술구조 및 Harness 안전 장치》

△ 기술 스택
▷ 프론트엔드: Astro 웹 프레임워크 (빠른 로딩 및 직관적인 컴포넌트 구조)
▷ 백엔드 및 에이전트: Node.js / Python 기반의 독립 실행 계층
▷ 데이터 스토어: 사용자 경험 데이터, 이력서 버전 기록, 면접 세션 저장을 위한 데이터베이스

△ 에이전트 실행 및 Harness 안전 가이드라인
▷ 1. 팩트 가드레일 (Fact Guardrail) 및 자가 검증기
   에이전트가 문장을 생성하거나 추천할 때, 사전에 정의된 '사용자 경험 자료실' 내부의 정보 범위만을 참조하도록 프롬프트를 제한(RAG Grounding)하고, 2차 백그라운드 검증 태스크를 실행하여 출처 미확인 정보를 필터링한다.
▷ 2. 도구 실행 시각화 (State radius card)
   에이전트가 검색이나 문서 분석 도구를 호출할 때, 사용자에게 진행 상황(호출 도구명, 실행 커맨드)을 미려한 UI 카드로 노출하여 블랙박스 현상을 방지한다.
▷ 3. 작업 영속성 (Persistence)
   장시간 실행되는 에이전트 분석 작업은 세션 ID 기반의 체크포인트를 설정하여 브라우저가 꺼지거나 네트워크가 끊겨도 마지막 상태부터 재개할 수 있도록 설계한다.

《8. 심사기준 대응 및 발표 전략》

△ 문제 정의 (15점)
▷ 단순히 "글 잘 쓰는 자소서 생성 AI"가 아님을 강조한다. 핵심 문제는 "공장형 이력서의 양산"과 "AI 환각으로 인한 서류 신뢰도 하락"임을 명확히 정의한다.

△ 기대 효과 (15점)
▷ 구직자는 불필요한 과장 없이 자신의 고유한 경험 팩트에 기반한 맞춤형 서류를 효율적으로 구성할 수 있으며, 기업은 환각이 배제된 검증 가능한 서류를 검토할 수 있어 채용 시장 전반의 신뢰 비용을 낮춘다.

△ 창의성 (20점)
▷ 라이너의 출처 표기법을 적용한 개인용 팩트 자가 검증 엔진, 사고 과정을 시각화한 모션 UI, 사용자가 제어권을 온전히 쥐는 'Deep Agent Canvas'의 독창성을 보여준다.

△ 기술구현 및 완성도 (40점)
▷ 불필요한 외부 연동은 모킹(Mocking) 처리하거나 장기 과제로 넘기고, 시작 ▷ 공고 분석 ▷ 경험 연결 ▷ 캔버스 부분 편집 ▷ 백그라운드 자가 검증 ▷ 면접 피드백으로 이어지는 **5대 핵심 기능의 시연 완결성**에 집중하여 100% 동작하는 프로토타입을 증명한다.

△ 발표 (10점)
▷ "이것저것 다 되는 만능 툴"이라는 과장 대신, 구직자 한 명이 Kairos를 활용해 실제로 환각 없이 독창적인 지원서와 면접 준비를 끝마치는 **'1인 사용자 시나리오'**를 시연과 함께 일관되게 설명한다.

예선 심사위원 3명의 피드백 정리

- 기존 선행 시스템 비교조사(시장조사) 점검 등)(점검은 차별성찾기 중점으로) 제네시스랩 -뷰티인 HR, 사람인-모의면접, 자소서 진단 등 
- 사용자 관점에서 이력서 면접 데이터를 보고 관리할수 있도록 인터페이스 구성이 필요
- 채용공고 정보제공에 대한 구체적인 모습 기획 필요

- 기존 비슷한 서비스들이 많으니 차별될 수 있는 추가기능(예: 여러 지원자 데이터로 내 순위 파악하기, 면접 응시 기능, AI 면접 피드맥에 대한 의견 수집 및 반영 시스템 구축) 등을 고려하면 좋을것으로 보인다.
- 발표시 충분한 서비스 내용을 설명할 필요가 있다.

- 먼저 지원회사나 지원 직무 조사를 선행하여 공부하고 이에 맞는 파편화 되어있는 자신의 이력이나 경력을 활용하는 시스템으로 완성도를 올리면 좋겠음
